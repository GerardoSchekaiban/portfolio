Enterprise configuration data product: a medallion architecture

Enterprise configuration data (sites, accounts, nodes, software, entitlements) is scattered across dozens of operational tables. This project designs a medallion architecture that turns those raw extracts into three reusable data products. Each layer has one job, and quality checks run before the next layer does.

Problem
Raw, duplicated, coded data from two instances of one source system
Approach
Bronze, silver and gold layers with quality gates
Output
Three gold products with history, read by BI and an LLM
My role
Architecture, data modelling and quality design

    Decision log

    The choices that shape the design, and what each one costs.

    LayerDecisionWhyTrade-off
    BronzeKeep sources exactly as received. No business logic, only load metadata.Any run can be replayed, and a bad rule can never corrupt the raw copy.Raw noise (duplicates, coded values) is stored and must be handled later.
    BronzeOne raw view per source instance.The two instances differ in scope: one holds many object types, the other only site-level data.Two inputs to reconcile in silver.
    SilverDefine each business entity once, in silver.Every product reads the same site, node and account definitions.Silver changes need care, because all gold products depend on it.
    SilverUnify both instances with a source_instance flag.One entity set for consumers, with the origin still visible.Rows from different instances can collide on keys, hence the conform step.
    SilverFlag records, never delete them.Nothing disappears silently, and consumers can filter on the flag.Downstream code has to apply the flags it cares about.
    SilverHeavy logic in tables, light logic in views.Expensive steps (site, node, lookup) run once per load. Simple ones stay fresh with no storage.Tables add refresh steps and storage.
    SilverGenerate a key for nodes with no serial number and flag them.The node stays countable and traceable instead of being dropped.A generated key is not a stable identity across sources.
    GoldRead only from silver, never from another gold product.One place for business definitions, and no hidden chains between products.Some joins are repeated across products.
    GoldKeep history as SCD Type 2, with a current view on top.A full audit trail, and the current view always returns one row per site.More rows, and a close-and-open step on every change.
    AllA failed quality gate keeps the previous version live.Consumers get data that is a day old but correct, instead of fresh but wrong.A persistent failure leaves data stale until someone fixes it.
